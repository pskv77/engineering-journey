# Retrospectives

This directory contains periodic reviews of the learning process.

Retrospectives are used to evaluate not only what was learned, but also whether the learning system itself is working effectively.

## Types of retrospectives

### Sprint retrospective

Performed after each learning sprint.

Typical questions:

- What improved?
- What remained difficult?
- What did I actually learn to do independently?
- Which tasks required too much help?
- Which learning resources were useful?
- What should be repeated?
- Does the next sprint need adjustment?

### Monthly retrospective

Looks at broader trends across several weeks.

Possible topics:

- skill-rank movement;
- consistency;
- Git activity;
- homelab development;
- project progress;
- course progress;
- recurring weaknesses.

### Major checkpoint retrospective

Performed after comprehensive assessments or major roadmap phases.

It may result in:

- Baseline v2;
- roadmap changes;
- reprioritization;
- specialization decisions;
- new target ranks.

## Core principle

The roadmap is allowed to change.

Changing the plan after receiving new evidence is not failure.

The purpose of retrospectives is to prevent blindly following an outdated roadmap.

## History

Previous retrospective documents should be preserved.

Git history should show how decisions and priorities changed over time.
