# Skills and Ranking System

This directory contains the skill model used to track engineering development over time.

The purpose of the ranking system is not to measure intelligence or academic performance.

It is used to estimate how independently and reliably I can apply a skill in practice.

## Skill ranks

### Rank 0 — No practical knowledge

The topic is unfamiliar or almost completely new.

Typical state:

- cannot explain the basic concepts;
- cannot perform a practical task;
- requires learning from the beginning.

### Rank 1 — Basic understanding

I know the main concepts and terminology.

Typical state:

- can explain some basics;
- can recognize correct solutions;
- can complete simple tasks with instructions, examples or significant help;
- practical knowledge is unstable.

### Rank 2 — Working basic skill

I can independently solve standard tasks, usually with documentation available.

Typical state:

- understand the main mechanisms;
- can perform common operations;
- can troubleshoot simple problems;
- can build small working solutions;
- still need references for syntax and less familiar situations.

### Rank 3 — Independent practical skill

I can independently solve typical real-world tasks.

Typical state:

- can design and implement standard solutions;
- can troubleshoot without step-by-step instructions;
- understand common failure modes;
- can explain technical decisions and trade-offs;
- can combine the skill with adjacent technologies.

### Rank 4 — Engineering level

I can work confidently with both typical and atypical problems.

Typical state:

- can design larger systems;
- understand deeper mechanisms and trade-offs;
- can diagnose complex failures;
- can optimize and improve existing systems;
- can make informed architectural decisions.

### Rank 5 — Deep mastery

I have deep technical understanding and extensive practical experience.

Typical state:

- can design complex systems from first principles;
- understand implementation details and internal mechanisms;
- can solve unusual or difficult problems;
- can teach the topic and review the work of others;
- can evaluate technologies and architectural approaches critically.

## Confidence scale

During assessments, answers may also include a confidence score.

### 0 — Not confident

The answer is mostly a guess or the concept is unknown.

### 1 — Low confidence

I have a hypothesis or partial memory but am unsure.

### 2 — Medium confidence

I believe the answer is correct but may be missing details.

### 3 — High confidence

I am confident in the answer and can explain the reasoning.

Confidence is tracked separately from correctness.

A confident incorrect answer is an important diagnostic signal.

A correct answer with confidence 0 may indicate recognition or guessing rather than active knowledge.

## How ranks are assigned

Ranks should be based on evidence rather than self-perception alone.

Possible evidence includes:

- diagnostic exams;
- hands-on labs;
- projects;
- troubleshooting tasks;
- code reviews;
- configuration reviews;
- work-related experience;
- repeated assessments;
- independent explanations.

Course completion alone does not automatically increase a rank.

## Skill progression

A rank should increase only when practical capability changes.

For example:

Rank 1 → Rank 2 means moving from:

"I understand the concept and can follow an example"

to:

"I can independently complete a standard task with documentation."

Rank 2 → Rank 3 means moving from:

"I can perform standard tasks"

to:

"I can independently solve typical real-world problems and troubleshoot them."

## Rechecks

Skills must be rechecked after time has passed.

The learning system should periodically test whether knowledge remains available without recent repetition.

Typical recheck interval:

- approximately 4–6 weeks after focused learning;
- later through comprehensive mixed assessments.

## Skill states

A low rank can represent different learning situations.

Examples:

- Rebuild — previously learned but largely forgotten;
- Restore — knowledge exists but active practice is weak;
- Systematize — fragmented practical experience without a coherent model;
- New branch — technology has not yet been properly learned;
- Maintain — existing strength should be preserved through continued use;
- Deepen — foundation exists and needs more engineering depth.

These states should influence how the learning roadmap is designed.

## Goal

The goal is not to reach Rank 5 in every skill.

The goal is to build:

- a strong and reliable technical foundation;
- several Rank 2–3 engineering capabilities;
- deeper Rank 3–4 specialization in selected professional areas over time.
